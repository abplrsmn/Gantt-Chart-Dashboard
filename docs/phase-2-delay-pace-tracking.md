# Phase 2 — Delay & Pace Tracking

## Goal
Move beyond visibility and begin identifying where projects are delayed and whether their pace is healthy.

## Duration
Week 3–4

## Main Focus
- detect delay by stage
- compare actual pace against expected movement
- identify near-deadline and behind-schedule projects
- surface project risk more clearly

## Scope
### 1. Delay Detection by Stage
For each project, identify:
- current delayed stage
- days remaining or days behind
- whether the issue sits in Design, Project Control, Project Management, or Handover

### 2. Pace Benchmark
Introduce a simple benchmark logic:
- expected progress based on time elapsed
- actual progress based on available status/progress input
- variance between actual and expected

### 3. Risk Flags
Recommended pace/risk classification:
- On Pace
- Slightly Behind
- Delayed
- Critical Delay

### 4. Near Deadline Detection
The system should highlight projects that are:
- close to end contract date
- already delayed
- at risk of delayed handover

## Deliverables
- delayed stage visibility
- near deadline list
- pace/benchmark basic logic
- project risk flagging

## What This Phase Does Not Fully Solve Yet
- detailed automatic blocker categorization for every case
- perfect forecast accuracy
- complete recovery-action automation

## Success Check
At the end of this phase, the team should be able to answer:
- where exactly the delay is happening
- which projects are moving too slowly
- which projects need immediate follow-up
