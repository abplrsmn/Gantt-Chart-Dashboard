# Phase 3 — Role & Ownership

## Goal
Make sure every role knows what they are responsible for and where they need to take action.

## Duration
Week 5–6

## Main Focus
- define role visibility
- assign ownership structure
- make reminder and follow-up targetable by role and unit
- ensure every active project has accountable roles attached

## Scope
### 1. Role Mapping
Roles should be structured clearly, for example:
- PIC
- Assignee
- Stakeholder
- Approver
- Requester
- Vendor
- Admin / Management

### 2. Ownership Rules
Each active project should ideally have:
- an owner role
- a follow-up role
- a current action owner
- a next action

### 3. Role-Based Visibility
The system should begin separating what different roles need to see.
Examples:
- PIC sees project execution concerns
- Approver sees pending approvals and impact
- Management sees summary, risks, and exceptions

### 4. Reminder / Audit Foundation
By this phase, reminder/audit logic should be usable for:
- role + unit bucket targeting
- summary logging
- admin oversight

## Deliverables
- role structure for project monitoring
- ownership model per project
- reminder/audit log structure
- role-aware summary direction

## What This Phase Does Not Fully Solve Yet
- full personalized delivery per individual person if people mapping is still incomplete
- final mature access-control model for every user type

## Success Check
At the end of this phase, a role owner should be able to answer:
- what projects are related to me
- what needs my action
- where my bottlenecks are
